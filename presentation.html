Hallazgos Críticos de Seguridad
  • Credenciales hardcodeadas — if(login.equals("admin")) · OWASP A07
  • CSRF deshabilitado — http.csrf().disable() · OWASP A01

Problemas de Arquitectura
  • God Class AbstractController — 5+ responsabilidades, 28% de toda la deuda
  • Field Injection — 11 usos de @Autowired, dificulta testing
  • Clases vacías — PersonController, CountryService sin lógica propia
  • FetchType.EAGER excesivo — N+1 queries, OutOfMemoryError potencial

Prácticas XP Recomendadas y Aplicadas

Rotación de roles conductor / navegador para revisión en tiempo real.

Build estable → tests mínimos → refactor controlado → hardening de seguridad.

08 · Conclusiones
Tratamiento de la Deuda Técnica
🔍 Detección de Smells y Refactorización

35+ code smells clasificados por severidad. Refactorizaciones concretas (Builder, DTO, Constructor Injection) que atacan los puntos de mayor riesgo en las clases base del sistema.

✅ Clean Code y Prácticas XP

Múltiples violaciones SOLID identificadas. Las prácticas XP — TDD, CI, Refactoring continuo, Small Releases — se incorporaron como hoja de ruta de transformación del proyecto.

👥 DevEx y Productividad (SPACE)

Alta carga cognitiva y flow limitado por deuda estructural. El equipo pasó de 0 a 16 clases de test, incorporó CI y dejó trazabilidad documental completa del proceso.

🔒 Deuda en Procesos — Sonar + Trivy

Pipeline CI/CD completo: Build → Tests → SonarQube → Trivy → GitHub Security. 76 issues, 621 min de deuda estimada, 7 hotspots todos revisados.

🧪 Deuda en Pruebas

Cobertura 0% → ~45%. 100+ pruebas unitarias con JUnit, MockMvc y Mockito. JaCoCo con umbrales mínimos como criterio de calidad institucionalizado.

📈 Resultado General
Security E → revisado Reliability D Maintainability A 0% → 45% cobertura

El proyecto es recuperable. La deuda está concentrada y manejable. El orden correcto: seguridad → estabilidad → testabilidad → limpieza.
