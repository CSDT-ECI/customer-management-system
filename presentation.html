¿Qué es Customer Management System?

Aplicación empresarial Java para gestión de clientes, personas y dashboards personalizados. Base de código legacy seleccionada para análisis académico de deuda técnica.

Stack Tecnológico

Objetivo del Curso CSDT

Identificar, analizar y documentar problemas de calidad, mantenibilidad, productividad y deuda técnica presentes en el sistema, aplicando herramientas y metodologías modernas.

08 · Conclusiones

Tratamiento de la Deuda Técnica

🔍 Detección de Smells y Refactorización

Se identificaron 35+ code smells clasificados por severidad. Las refactorizaciones propuestas (Builder, DTO, Constructor Injection, Extract Class) atacan los patrones de mayor riesgo, especialmente en las clases base AbstractController y AbstractService.

✅ Clean Code y Prácticas XP

La evaluación reveló múltiples violaciones SOLID. Las prácticas XP (TDD, CI, Refactoring continuo, Small Releases) se incorporaron como hoja de ruta para transformar el proyecto de legacy a mantenible.

👥 DevEx y Productividad

El framework SPACE evidenció alta carga cognitiva y flow limitado. El equipo mejoró la productividad habilitadora: pasó de 0 a 16 clases de test, incorporó CI y dejó trazabilidad documental completa.

🔒 Deuda en Procesos — SonarQube + Trivy

El pipeline CI/CD con GitHub Actions automatiza Build, Unit Tests y análisis estático. SonarQube reveló 76 issues con 621 min de deuda estimada. Trivy complementa con escaneo de CVEs en dependencias y detección de secrets.

🧪 Deuda en Pruebas

Cobertura inicial 0% → ~45% final. Se incorporaron 100+ pruebas unitarias con JUnit, MockMvc y Mockito. JaCoCo configurado con umbrales mínimos (55% líneas, 10% ramas) como criterio de calidad.

📈 Resultado General

El proyecto es recuperable. La deuda está concentrada y el costo es manejable. La prioridad: seguridad primero, luego estabilidad estructural, luego testabilidad y finalmente limpieza incremental.
